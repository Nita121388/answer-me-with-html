## Foldable tree nodes

`tree list fold` makes every node that has children foldable: the reader clicks a node to open and close it, and the whole subtree goes with it. There is no script of ours in it — the node is a native `<details>`, so the browser does the folding, the keyboard works (Tab to the row, Enter or Space to toggle), and any depth folds on its own. `fold open` starts every node open. `am help tree` gives the syntax.

```tree list fold
src/
  components/ | renders the tree
    tree.js
    flow.js
  runtime/
```

- A node carries its note on the folding line, so a closed node still says what it holds.
- `fold` implies the indented list: an org chart computes its boxes and lines up front and cannot fold. A tree with more than 4 children already falls to the list, so the coverage is wide.
- Printing shows every node open, because a closed `<details>` hides its content from the page and the print layout. The page script opens them when printing starts and puts the reader's own folds back afterwards, the way folding panels already worked.
- A video leaves the fold out and says so: its steps open the tree a line at a time, which a closed node would fight.
- The triangle that opens a node is drawn by the theme, not by the browser: it sits in the connector column, turns as the node opens, and takes the theme's ink, so it reads as a control and not as part of the line. Right-to-left pages mirror it, and a reader who asks for less motion gets no turn.
- A tree without `fold` renders exactly as it did: the markup, and the output, are byte for byte the same.

## Mark the row of a node that folds

A foldable node's row is now something a reader can mark, and can ask a question about: turn on Remark and click the row — the node does not fold, the note box opens, and a click on the note opens it again without folding either. Reply carries the panel, the row's text and the reader's words. A leaf node could be marked before; the row of a node that folds is the one a reader most often wants to ask about.

## 树节点可折叠

`tree list fold` 让每个有子节点的行都能折叠：读者点一下节点就打开或收起，整棵子树跟着走。这中间没有我们自己的脚本——节点是原生 `<details>`，收放由浏览器完成，键盘可用（Tab 到该行，回车或空格切换），任意深度各自独立。`fold open` 让所有节点默认展开。语法见 `am help tree`。

```tree list fold
src/
  components/ | 组件渲染
    tree.js
    flow.js
  runtime/
```

- 节点的备注留在折叠行上，收起时仍能看到它装了什么。
- `fold` 自带缩进列表模式：组织结构图的方框和连线是预先算好的，做不了折叠。子节点超过 4 个的树本来就会落到列表模式，所以覆盖面够。
- 打印时所有节点展开，因为关闭的 `<details>` 会把内容对页面和打印布局都藏起来。页面脚本在开始打印时展开、打印后把读者自己的折叠状态放回去——和面板折叠一直是同一套做法。
- 视频模式不折叠并给出提示：视频的步骤本身就是逐行展开树，折叠会跟它打架。
- 展开节点的三角由主题绘制，不用浏览器原生那个：它排在连线那一列，展开时转动，取主题的墨色，读起来是控件而不是线的一部分。从右到左的页面会镜像，读者要求减少动效时不转动。
- 不带 `fold` 的树渲染结果和以前完全一致：标记与输出逐字节相同。

## 可折叠节点的行也能标记提问

可折叠节点的行现在可以标记、也可以对它提问：打开 Remark 再点该行——节点不会折叠，备注框弹出；点那条备注也只打开备注，不折叠。Reply 会带回面板号、该行文字和读者的话。叶子节点本来就能标记；而「可折叠节点的行」恰恰是读者最想问的那一行。
